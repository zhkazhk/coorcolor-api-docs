<2 id="b-assign">Assign an engineer to an order

Call this endpoint to attach an engineer to an existing print-service order and move the order to processing. The handler copies the engineer's id, name and phone onto the order, appends a timeline entry, and returns the full updated order. Use it from admin or dispatch screens where a staff member picks an engineer for a job.

<3 id="b-request">Request
Name In Type Required Description
id path string yes Order id, as returned by POST /api/orders in data.id.
engineer_id body string yes Engineer id of an existing engineer record, for example engineer001. A missing, empty or otherwise falsy value is rejected.

Send the body as JSON:

{
  "engineer_id": "engineer001"
}
curl -X PUT "https://<HOST>/api/admin/orders/<ORDER_ID>/assign" \
  -H "Content-Type: application/json" \
  -d '{"engineer_id":"engineer001"}'
<3 id="b-response">Response

Success returns HTTP 200 with code set to 0 and data holding the complete updated order document:

{"code":0,"data":{"id":"<ORDER_ID>","order_no":"<ORDER_NO>","service_type":"repair","brand":"HP","model":"","problem_desc":"Drum unit replacement","urgency":"normal","photos":[],"position":null,"appointment_date":"2026-11-04","appointment_time":"09:30","contact_name":"Wang Fang","contact_phone":"13900000003","service_address":"Floor 6, 1000 Century Avenue, Pudong, Shanghai","remark":"","status":"processing","created_at":"<ISO-8601>","updated_at":"<ISO-8601>","engineer_id":"engineer001","engineer_name":"张工程师","engineer_phone":"13800138001","timeline":[{"status":"processing","time":"<ISO-8601>","operator":"管理员","remark":"分配给工程师：张工程师"}]}}

Compared with the order before the call, engineer_id, engineer_name and engineer_phone now hold the engineer record's values, status is processing, updated_at is refreshed, and one timeline entry was appended. Every other field is unchanged.

<3 id="b-errors">Errors

Every failure returns {"code":-1,"message":"..."}. There are no machine-readable error codes, so match on the message string.

HTTP message When it happens What to do
400 请选择工程师 engineer_id is missing, empty or otherwise falsy. Raised before the order is looked up. Require an engineer selection in the UI and block the call until one is set.
404 订单不存在 No order matches id. Refresh the order list; the order may have been removed.
404 工程师不存在 No engineer matches engineer_id. Raised after the order resolves. Reload the engineer list and send an id that still exists.
<3 id="b-behaviour">Behaviour worth knowing
  • The handler writes five things: the three engineer fields (engineer_id, engineer_name, engineer_phone), status set to processing, a new timeline entry, and a refreshed updated_at. The timeline entry is {"status":"processing","time":"<ISO-8601>","operator":"管理员","remark":"分配给工程师：<engineer name>"}.
  • Checks run in a fixed order: body first, then order, then engineer. Because the body check comes first, an unspecified engineer_id returns 400 even when the order is also wrong; because the order check comes before the engineer lookup, an unknown order returns 订单不存在 and hides an unknown engineer.
  • No token check runs in this handler. Nothing on the server enforces admin rights here, so treat access control as outside this endpoint and do not rely on it to reject a caller.
  • status is set to processing unconditionally; there is no state guard. Assigning an order that is already completed silently reopens it, and the timeline gains a processing entry with no corresponding completed reversal.
  • Re-assigning an order that is already processing succeeds and appends another timeline entry, so the timeline can hold several assignment records.
