Two drafts of one page, one verdict

The same brief, sent to two independent drafting sessions, produced two versions of the assign-endpoint page. This is the review: the scores, the defects each draft carries, and a verdict with one line of reasoning and support tags that point at the pages I checked.

The brief

Both drafts received identical input: the ground truth for PUT /api/admin/orders/:id/assign (source range, request fields, the captured success payload, all three failure strings, the check order, the absent authorization check and the absent state guard), a required section order, an HTML tag allowlist, an escaping rule, and a length target of 350-500 words. Neither saw the rubric, the other draft, or the site's stylesheet.

What each draft got right

  • Both reproduced all three failure strings exactly, with the correct HTTP statuses and the correct check order (body, then order, then engineer).
  • Both stated that the handler performs no token check, in the plainest words either draft used — this is the fact a writer is most tempted to soften, and neither did.
  • Both noticed the consequence of the missing state guard: assigning a completed order reopens it. Draft B adds that the timeline then has no matching reversal entry, which is the sharper observation.
  • Both kept Chinese wire values untranslated inside code, and both proposed a concrete client-side change in the “what to do” column.

Verdict

preferred: Draft A recommended for the published page

One line of reasoning: Draft A enumerates four write effects and lists four, while Draft B claims five and lists four — the only accuracy defect either draft carries — and A is no weaker on completeness, actionability or tone, so the accuracy-first rule decides without arithmetic.

Support tags, each pointing at a page checked during this review:

  • [API-ref] assign → Behaviour worth knowing — the four write effects and the unguarded status, verified against server/index.js:1041-1052.
  • [API-ref] Authentication → Routes without authorization — the “no token check” claim that both drafts make, verified against the handler body.
  • [error-catalog] E-ASG-MASK — the check-order consequence both drafts describe, re-read against the captured pair.

What this demonstrates, and what it does not

  • It demonstrates a review procedure that a second reviewer can repeat: a brief fixed in advance, independent drafts, a defect list with evidence, a decision rule applied before scoring preferences were known, and tags that resolve.
  • It does not demonstrate that one model writes better documentation than another. Both drafts came from the same model in separate sessions. The gap between them is small, which is itself the honest finding: at this level of specificity the brief determines most of the quality, and the reviewer's job is to catch the residue.
  • It also does not show what a different brief would produce. Drafts optimise what the brief asks for — here, completeness of the error table — and the published page was rewritten afterwards to add the state-machine table both drafts lacked.
The published page is not Draft A

Neither draft was published. The reference page keeps the best sentences from both, adds the state-machine table, and replaces every hand-written example with a captured pair — which is exactly the edit a review is supposed to make possible.
