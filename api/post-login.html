POST/api/login

Administrator sign-in

Exchanges an administrator username and password for a 24-hour JWT. This is the only sign-in the service has; the mini program's users have no equivalent.

Source
server/index.js:59-70
Auth required
No
Token lifetime
24 hours (expiresIn: '24h')
Rate limit
None — see the note below

Request

NameInTypeRequiredDescription
usernamebodystringYesAdministrator username. Seeded as admin on first start.
passwordbodystringYesPlain password over the wire; compared against a bcrypt hash, never stored.

Response

A successful sign-in returns the token and the username it belongs to. The token payload is {id, username}, so it carries no phone number and cannot identify a mini-program user (see token shapes).

FieldNotes
data.tokenHS256 JWT, signed with the server secret, valid for 24 hours.
data.usernameEcho of the account name; safe to show in the console header.

Errors

HTTPmessageWhen it happensWhat to do
HTTP 401用户不存在No administrator record matches username.Check the account name. Do not surface this text as-is: it tells the caller the account does not exist.
HTTP 401密码错误The account exists and the bcrypt comparison fails.Re-enter the password. Same status as the row above, different string.
Two 401s, one guessable difference

The two messages differ, so a script can enumerate administrator names. There is no lockout and no throttle on this route. See E-AUTH-ENUM.

Behaviour worth knowing

  • bcrypt.compareSync runs on the request thread, so the event loop blocks for the duration of the hash — tens of milliseconds per attempt, which is also the only accidental brake on guessing.
  • The token is the whole session. There is no revocation list, so signing out on the client (wx.removeStorageSync('token')) does not invalidate a copy that is already in the wild.
  • The failed attempt returns 401 with the envelope, while an unregistered path returns 404 with 请求的资源不存在. Both carry code: -1.
