POST/api/wxpay/create-order

Create a payment order

Stores a rental order, calls the payment platform's unified order endpoint, and returns the parameters a mini program passes to wx.requestPayment.

About the examples on this page

This endpoint is the only one whose outbound call reaches a third party. The captures below were recorded against a sandbox copy of the service: unifiedOrder and queryOrder are stubbed, and the merchant key is a dummy. The parameter names, the MD5 signing order and the response shape are the real implementation; the signature value is not reproducible outside the sandbox.

The amount is not verified

The handler reads totalAmount from the body, stores it, and converts it for the payment platform (server/index.js:1657). The product records are never consulted, so the price catalogue on the GET /api/products page has no bearing on what is charged. Twelve rentals at ¥899 each, submitted as one fen:

Do not ship this as-is

A client controls the payable amount. The fix belongs in this handler: load each productId, recompute the total from the stored price, and reject the body when totalAmount disagrees. E-PAY-AMOUNT records the evidence.

Errors

HTTPmessageWhen it happensWhat to do
HTTP 400参数不完整items is empty, or totalAmount is zero or absent, or openid is missing. One message covers all three.Send all three. Reuse an openid already obtained for the session; do not mint one per attempt.
HTTP 500微信支付功能未配置The payment utility module failed to load at start-up.Check the server log at boot; the module is loaded in a try/catch and the failure is only printed.
HTTP 500创建订单失败The unified order call failed or timed out. The stored order is left in pending.Retry, and reconcile afterwards with GET /api/wxpay/order/:orderNo rather than creating a second order.

Behaviour worth knowing

  • The order is written to storage before the platform is called, so a failed payment attempt leaves a pending order behind. Nothing expires it.
  • Product stock is not touched: this path is separate from POST /api/orders/buy, which does decrement stock and apply coupons.
  • Math.round(totalAmount * 100) is the only conversion. A fractional yuan amount is rounded, not rejected.
  • There is no idempotency key. Two submissions create two orders and two prepay attempts.
