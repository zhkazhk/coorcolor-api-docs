GET/api/products

List products

Returns the catalogue the shop renders: repairs, rentals and supplies in one list, filterable by category, with inactive items hidden unless asked for.

Source
server/index.js:780-798
Auth required
No
Pagination
None — the whole catalogue is returned
Sort
created_at descending

Request

NameInTypeRequiredDescription
categoryquerystringNoOne of repair, rent, supplies, sale. Any other value, including all, disables the filter.
includeInactivequerystringNoThe literal string true includes products whose status is not active. Any other value keeps them hidden.

With a category, the list narrows to that category:

Response

FieldNotes
data[]Array of product objects, newest first. Ten are seeded on first start.
idStable string such as product001; use it in POST /api/orders/buy.
pricePrice per unit in CNY, a number.
originalPriceList price, for a strike-through. Defaults to price.
stockUnits available. Decremented by a purchase, never restored by a cancellation.
salesUnits sold, used for ranking. Incremented on purchase.
statusMay be absent on older records; absence means active.
featuresArray of short selling points, rendered as tags.
imageEither an emoji or an image URL. Render both, they are not distinguishable by type.

Rules that are not in the parameters

  • The status filter reads !p.status || p.status === 'active'. A product with an empty or missing status is therefore visible, which is how the ten seeded rows behave — do not treat a visible product as proof of an explicit active flag.
  • There is no pagination and no limit. The response is the entire catalogue on every call, which is fine at ten rows and is the first thing to change if the catalogue grows past a few hundred.
  • GET /api/products/:id answers 404 产品不存在 for an unknown id, but does not filter on status — a de-listed product still resolves by id.

Errors

The list itself has no failure path: an unknown category returns an empty array with HTTP 200 rather than 400, so a typo in the query string looks like an empty catalogue. The only 404 on the product routes is the detail call above.
