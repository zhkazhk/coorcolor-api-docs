Reference

API reference

The CoorColor back office speaks JSON over HTTP on port 3000. Every response is wrapped in the same envelope, there are no machine-readable error codes, and most admin routes perform no authorization check. Read the authentication page before the endpoints.

Conventions

Base URL
http://localhost:3000 in development; the deployed base is the reverse-proxied host. Paths below are absolute, so append them as-is.
Content type
application/json for every request and response except the payment callback, which is XML in both directions.
Auth
Bearer JWT where present. Several admin routes accept unauthenticated calls — the meta column below is generated from the contract, so it says which.
Encoding
message is Chinese prose, UTF-8. Treat it as display text.
Time
ISO-8601 UTC strings for stored timestamps; YYYY-MM-DD for appointment dates.

The envelope, the Bearer rule and the two token shapes are on Authentication and errors.

Documented in depth

EndpointPageWhy this one
POST /api/loginAdministrator sign-inThe only way to obtain a token, and the two 401s that leak whether an account exists.
POST /api/user/send-codeSend a verification codeValidation that checks length only, and a delivery path that ends in a console log.
GET /api/productsList productsThe catalogue powering the shop: two filters, no pagination, one implicit status rule.
POST /api/ordersCreate a service orderEight validation rules joined into one string, and an identifier made of a timestamp.
GET /api/orders/:idRead an orderReads that enrich the record with engineer data not stored on it.
PUT /api/admin/orders/:id/assignAssign an engineerWhere the state machine is decided, and where two of its rules contradict each other.
POST /api/wxpay/create-orderCreate a payment orderMoney: the amount is taken from the request body without recomputation.
POST /api/wxpay/callbackPayment callbackA callback that cannot verify a signature, because its XML body is never parsed.
